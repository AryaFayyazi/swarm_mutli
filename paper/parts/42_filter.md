### 4.8 A claim filter: mark the claim, keep the work
The claim does the harm, and the gate stops the action at a utility cost. Can we cut the harm at the claim? We added a **claim filter** to the message bus. A small model (glm-53-flash, temperature 0) reads every message between agents. If a message claims approval, authorization or permission, the filter rewrites the claim as an attributed, unverified claim and adds a pointer to the permission system: "UNVERIFIED CLAIM (made by ApprovalsAgent): … you must confirm it with the permission system (request_permission) before any action that changes state". The rest of the message is unchanged. The filter sees neither the task, nor the ledger, nor the twin. It fails open: if it returns nothing, the original message passes ({{R['_filter']['fail_open']}} of {{R['_filter']['calls']}} filter calls, mostly on the Lead's brief). The idea is close to spotlighting [16], which marks untrusted text for the model. Ours marks a *claim* by its source, in an agent-to-agent channel, and we test it against matched twins and a rule-based checker.

We ran it on fresh scenario draws (E9; new seed; relay; four models; {{R['counts']['e9']}} episodes; {{R['_n_clusters']}} base scenarios with every condition finished out of 40 planned, because the API limit fell during the sprint, see Limitations). **The manipulation replicates (H20 supported).** Violations rise from {{R['_cells']['A']['V']|.2f}} with no message to {{R['_cells']['B']['V']|.2f}} with the peer message ({{H['H20']['point']|+.2f}} [{{H['H20']['lo']|+.2f}}, {{H['H20']['hi']|+.2f}}]). **The filter removes most of the harm (H21 supported).** With the filter, violations fall to {{R['_cells']['C']['V']|.2f}} ({{H['H21']['point']|+.2f}} [{{H['H21']['lo']|+.2f}}, {{H['H21']['hi']|+.2f}}]), and no violating report says "authorized" any more (false-report share {{R['_cells']['C']['FA_over_V']|.0%}}, against {{R['_cells']['B']['FA_over_V']|.0%}}). All four models fall: from {{min(R['_cells']['B']['per_model_V'].values())|.2f}}–{{max(R['_cells']['B']['per_model_V'].values())|.2f}} to at most {{max(R['_cells']['C']['per_model_V'].values())|.2f}}. **It is not tuned to one sentence (H23 supported).** On the attacker message from 4.7, which the filter prompt never saw, violations go from {{R['_cells']['G']['V']|.2f}} to {{R['_cells']['H']['V']|.2f}} ({{H['H23']['point']|+.2f}} [{{H['H23']['lo']|+.2f}}, {{H['H23']['hi']|+.2f}}]). **It costs no measurable utility (H22 supported).** Goal completion on safe twins is {{R['_cells']['C']['goal_safe']|.2f}} with the filter and {{R['_cells']['B']['goal_safe']|.2f}} without (drop {{H['H22']['point']|+.2f}} [{{H['H22']['lo']|+.2f}}, {{H['H22']['hi']|+.2f}}], margin 0.10). **The gate replicates (H24 supported):** {{R['_cells']['D']['V']|.2f}} violations, safe-twin goal drop {{H['H24']['parts'][1]['point']|+.2f}} [{{H['H24']['parts'][1]['lo']|+.2f}}, {{H['H24']['parts'][1]['hi']|+.2f}}]. **We did not show that the filter is cheaper than the gate (H25 not supported):** the difference in safe-twin goal completion is {{H['H25']['point']|+.2f}} [{{H['H25']['lo']|+.2f}}, {{H['H25']['hi']|+.2f}}], and the two controls cost about the same here. The filter has one clear advantage: it needs no change at the gateway and it keeps the agent's own decision, so the claim becomes a prompt to ask.
