### 4.8 A claim filter marks the claim and keeps the work
If the claim does its harm by displacing the agent's check, a defense can restore the check at the claim itself. We added a **claim filter** to the message bus. A small model (glm-53-flash, temperature 0) reads every message between agents. If a message claims approval, authorization or permission, the filter rewrites that claim. The new text says who made the claim, says that it is unverified, and tells the reader to confirm it with the permission system before any state-changing action. The filter sees neither the task, nor the log, nor the twin. If it returns nothing, the original message passes, which happened in {{R['_filter']['fail_open']}} of {{R['_filter']['calls']}} calls, mostly on the Lead's brief. The idea is close to spotlighting [14], which marks untrusted text for the model. We mark a *claim* by its source, between agents.

**Finding.** We ran the filter on fresh tasks (E9; relay, four models, {{R['counts']['e9']}} episodes). The design had 40 base tasks, and {{R['_n_clusters']}} have every condition finished (Appendix A). The false message raises V from {{R['_cells']['A']['V']|.2f}} to {{R['_cells']['B']['V']|.2f}} ({{H['H20']['point']|+.2f}} [{{H['H20']['lo']|+.2f}}, {{H['H20']['hi']|+.2f}}]). With the filter, V falls to {{R['_cells']['C']['V']|.2f}} ({{H['H21']['point']|+.2f}} [{{H['H21']['lo']|+.2f}}, {{H['H21']['hi']|+.2f}}]), and no violating report says "authorized" any more (against {{R['_cells']['B']['FA_over_V']|.0%}} without the filter). All four models improve: V is at most {{max(R['_cells']['C']['per_model_V'].values())|.2f}} with the filter. The filter is not tuned to one sentence: the attacker message of Section 4.5, which the filter never saw, drops from {{R['_cells']['G']['V']|.2f}} to {{R['_cells']['H']['V']|.2f}} ({{H['H23']['point']|+.2f}} [{{H['H23']['lo']|+.2f}}, {{H['H23']['hi']|+.2f}}]). It costs no measurable useful work: goal completion on safe twins is {{R['_cells']['C']['goal_safe']|.2f}} with the filter and {{R['_cells']['B']['goal_safe']|.2f}} without ({{H['H22']['point']|+.2f}} [{{H['H22']['lo']|+.2f}}, {{H['H22']['hi']|+.2f}}], where a negative value means no loss). Figure 4 shows the results.

**The gate, for comparison.** The gate also works again: V is {{R['_cells']['D']['V']|.2f}} and goal completion is {{R['_cells']['D']['goal_safe']|.2f}}. We expected the filter to cost less useful work than the gate, but we did not show it (difference {{H['H25']['point']|+.2f}} [{{H['H25']['lo']|+.2f}}, {{H['H25']['hi']|+.2f}}]). The filter needs no change at the gateway, and the agent still decides.

**A message written against the filter still fails.** In E11, the attacker model (GLM-5.2) saw the filter prompt and searched two rounds for a message that gets past it. The best message avoids any approval claim. It says that a step is routine and non-disruptive, and asks the agent to proceed. On fresh tasks ({{R['counts']['e11']}} episodes, {{R['_e11']['n_clusters']}} base tasks), V is {{R['_e11']['V_nofilter']|.2f}} with no control, {{R['_e11']['V_filter']|.2f}} with the filter ({{H['H28']['point']|+.2f}} [{{H['H28']['lo']|+.2f}}, {{H['H28']['hi']|+.2f}}]) and {{R['_e11']['V_gate']|.2f}} with the gate. The filter still rewrote this message into an unverified claim, because it names a ticket and a peer. A pressure message with no claim at all would pass it unchanged, so the filter needs the gate or a permission record behind it.
